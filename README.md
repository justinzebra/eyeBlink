# Blink Assist — 眨眼輔助控制系統

React 前端控制介面，加上 ESP32 韌體。前端可以在兩種設備之間切換：

- **模擬設備**（預設）：完全在瀏覽器裡執行，不需要硬體，不會有任何馬達轉動。
- **ESP32 實機**：透過藍牙控制已燒錄韌體的 ESP32-WROOM-32，驅動 MG90S 伺服馬達。接線與燒錄見 [`firmware/README.md`](firmware/README.md)。

**實機模式僅供桌面模型測試。** 尚未完成機械限位、力量限制、故障釋放與醫療安全驗證，不可用來驅動真人眼瞼。韌體目前只確認能編譯，尚未在實體硬體上驗證。

## 第一次使用（Windows）

1. 到 [Node.js 官方網站](https://nodejs.org/zh-tw) 下載 LTS 安裝程式。依畫面安裝，保留 npm 與加入 PATH 的預設選項。**需要 Node.js 20.19 以上**（建議 22 或 24 LTS）；較舊的版本無法執行本專案使用的 Vite 7。
2. 安裝後重新開啟 PowerShell，輸入 `node --version` 與 `npm --version`，確認版本符合上述要求。若使用 nvm-windows，可執行 `nvm install 22` 再 `nvm use 22`。
3. 在 PowerShell 依序輸入（不用輸入程式碼框的反引號）：

```powershell
cd C:\eyeBlink   # 換成你放專案的資料夾
npm install
npm run dev
```

4. 保持 PowerShell 開著，以 Edge 或 Chrome 開啟終端機顯示的網址，通常是 [本機網頁](http://127.0.0.1:5173/)。網頁不需帳號，也不使用雲端服務。
5. 按「連接模擬設備」。畫面應顯示「模擬設備已連線」。你不需要插上 ESP32。
6. 停止網頁伺服器：回到 PowerShell 按 `Ctrl+C`。下次使用只需執行 `npm run dev`。

若 PowerShell 說無法執行 npm.ps1，使用 `npm.cmd install`、`npm.cmd run dev`，不必放寬系統執行原則。若 5173 已被使用，Vite 會顯示另一個埠，請依顯示網址開啟。

## 五個頁面的測試方式

### 控制總覽

- 連接後查看日間、夜間、左右模型位置、下次眨眼、下次排程和最後同步。
- 按「中斷連線」，讀取／儲存／套用按鈕應停用。畫面仍可能顯示最後的模型資料；它不是實體設備狀態。
- 再次連接會模擬重新載入最後儲存設定，未儲存的編輯會被取代。

### 日間模式

1. 啟用日間模式，設定間隔 10 秒、閉眼 500 毫秒、停留 300 毫秒、睜眼 500 毫秒。
2. 修改後狀態為「尚未儲存」，套用按鈕停用。
3. 按「儲存設定」：先顯示「儲存中」，成功後顯示「已儲存，尚未套用」。這時執行設定尚未變動。
4. 按「套用設定」後才會更新模擬設備的執行參數。按「模擬執行」，觀看睜眼 → 閉眼 → 停留 → 睜眼。
5. 等待十秒，觀察自動眨眼。間隔定義是開始到下一次開始，包含動作本身所需的時間。
6. 停用日間模式，儲存並套用後，不再自動眨眼；仍可手動觸發軟體預覽。

### 夜間模式

- 開啟手動夜間開關，模型應保持閉眼。關閉後恢復依排程判斷，不會強制覆蓋正在執行的夜間排程。手動夜間是即時指令：立即生效、不需要儲存或套用，也不會寫入儲存區；狀態列不會因此變成「尚未儲存」，重新啟動或重新連線後一律回到關閉。
- 啟用自動排程，設為 22:00–07:00，先只選星期一，儲存並套用。
- 在右側「排程模擬工具」依序指定：2026/11/09 21:59（日間）、22:00（夜間）、2026/11/10 06:59（夜間）、07:00（日間）。按「前往模擬時間」觀察來源與模型。
- 星期表示**開始日**。週一 22:00–週二 07:00 屬於週一，不需選週二。每個星期按鈕可獨立切換。
- 測試手動優先：在排程外開啟手動夜間，仍保持閉眼；在排程內解除手動，仍由自動排程維持閉眼。
- 測試完按「恢復實際時間」。時鐘使用瀏覽器／電腦本地時區，未實作設備時區同步。

### 馬達設定

- 左右閉眼參考角度預設為未設定，避免把展示值當作安全校正值。睜眼固定 0°。
- 分別輸入左側 30°、右側 40°，按儲存、套用。模擬眨眼時兩側角度應分別改變並回到 0°。
- 測試「複製左側至右側」與「還原角度預設值」，這些只修改編輯值，仍需儲存／套用。
- 0–90° 僅是展示限制，**不是人體安全範圍**。參考值已設定也不代表實體校正完成。

### 設備設定

- 最上方的「設備類型」可在模擬設備與 ESP32 實機之間切換；切換後頁面會重新載入，選擇會被記住。以下步驟以模擬設備為例。
- 可以連接、中斷、讀取、儲存及套用。
- 修改設備名稱並按「儲存設備名稱」，名稱獨立持久化。
- 修改時間參數後先儲存、不套用，再按「模擬設備重新啟動」：應載入剛儲存的設定並執行。
- 修改但不儲存，再重新啟動：應恢復最後儲存版本。
- 重新整理網頁、連接模擬設備，仍應讀到儲存資料。資料依瀏覽器及網址（含埠）分開；清除網站資料會移除模擬設定。
- 「讀取設定」會取代目前未儲存的編輯，但不自動套用。連線、讀寫錯誤與儲存空間不足會顯示錯誤，失敗不宣稱成功。

## 儲存、套用與關閉網頁的差異

| 資料          | 位置                       | 用途                         |
| ------------- | -------------------------- | ---------------------------- |
| 編輯中 draft  | settingsStore              | 表單尚未儲存的變更           |
| 已儲存 saved  | Mock Device + localStorage | 模擬設備重啟載入來源         |
| 執行中 active | Mock Device                | 模型動作與排程真正使用的設定 |

Mock Device 的持久化鍵是 `blink-assist.mock-device.v2`，內容包含 `settings` 與設備名稱。設定介面符合 `BlinkSettings`；數值單位為毫秒，時間格式為 `HH:mm`，星期是 0（日）到 6（六）。`validateSettings` 會同時在表單與設備儲存邊界驗證。

模擬版本與瀏覽器共用生命週期。**關閉網頁後無法繼續執行模擬動作**；重新開啟並連接會依持久化設定與當下時間恢復判斷，不補播關閉期間的眨眼。分頁背景節流時依時間重新計算動作。第一階段不宣稱具備真實設備的離線執行能力。

同一時間只允許一個分頁連接模擬設備（以瀏覽器的 Web Locks 實作）。第二個分頁按連線時會顯示「模擬設備已在另一個分頁連線」；先在原分頁中斷連線或關閉它即可。有未儲存的修改時，關閉或重新整理分頁前瀏覽器會先詢問。目前所在頁面記錄在網址（例如 `#/night`），重新整理後會停留在同一頁。

狀態列的文字由三份設定即時比對得出：「尚未儲存」（draft ≠ saved）、「已儲存，尚未套用」（saved ≠ active）、「已套用」（三者一致）。

## 專案結構

```text
src/
  domain/          純邏輯，不依賴 React、store 或瀏覽器 API
    settings.ts        設定型別、預設值、比較與複製
    validation.ts      設定驗證與數值範圍（表單與設備共用同一份）
    schedule.ts        夜間排程判斷
    blinkTimeline.ts   眨眼時間軸與眼瞼姿態計算
  device/          設備層，不依賴 React 或 store
    deviceService.ts   DeviceService 介面、模擬專用的 SimulationTools、韌體安全驗證介面
    types.ts           設備狀態型別
    deviceKind.ts      記住使用者選擇的設備類型
    index.ts           依設備類型建立對應的實作
    mock/              模擬設備、localStorage 儲存、跨分頁鎖
    ble/               Web Bluetooth 實作與協議編解碼
  stores/          Zustand：設備操作（deviceStore）、表單編輯（settingsStore）、同步狀態推導
  hooks/           模擬時鐘、同步狀態、網址路由、離開前警告
  components/      共用按鈕、輸入元件與雙眼模型
  pages/           五個繁體中文頁面
  app/             外框（側邊欄、頂列、狀態列）與頁面清單
  styles/          依載入順序拆成 base / shell / components / responsive
  lib/ test/       時間格式化、依設備類型變化的介面文字；測試共用工具
firmware/
  BlinkAssist/     ESP32 韌體（Arduino IDE 專案）
  README.md        接線、燒錄與故障排除
docs/
  ble-protocol.md  前端與韌體之間的藍牙通訊協議
```

依賴方向固定為 `domain ← device ← stores ← hooks/components/pages/app`，反向引用會被 ESLint 擋下（規則在 `eslint.config.js`）。幾個維護時的原則：

- **新增設定欄位**：改 `domain/settings.ts` 的型別與預設值 → `domain/validation.ts` 加驗證 → 頁面加輸入元件。範圍數值只寫在 `validation.ts`，頁面從那裡取用。
- **新增頁面**：在 `app/pages.ts` 加一筆，側邊欄與路由會自動跟上。
- **新增設備操作**：先加到 `DeviceService` 介面，再於 `deviceStore.ts` 加一個 action；頁面只呼叫 store 的 action，不直接碰設備。
- **設定一律以新物件取代**，不要就地修改（`defaultSettings` 已凍結，誤改會直接報錯）。
- 不需要 React 經驗也能先從 `pages/` 的文字修改開始，儲存檔案後 Vite 會自動更新畫面。

## 驗證與正式建置

```powershell
npm run check     # 格式、ESLint、型別檢查、測試，一次跑完；提交前請先執行
npm test          # 只跑測試
npm run test:coverage
npm run format    # 以 Prettier 自動排版
npm run build
npm run preview
```

測試涵蓋排程起迄與跨日／跨週、眨眼時間軸、設定驗證、模擬設備（連線、儲存／套用、重新啟動、儲存失敗、資料損壞、改名、跨分頁互斥）、store 的操作流程與同步狀態，以及各頁面的渲染冒煙測試。`npm run build` 先檢查 TypeScript，再產生 `dist/`。`npm run preview` 可本機檢查正式版，依終端機網址開啟。不要直接雙擊 `dist/index.html`，須以 HTTP 伺服器提供。

## 使用 ESP32 實機

1. 依 [`firmware/README.md`](firmware/README.md) 接線，並用 Arduino IDE 把 `firmware/BlinkAssist` 燒錄到 ESP32-WROOM-32。
2. 啟動前端，用電腦版 Chrome 或 Edge 開啟（Web Bluetooth 需要 localhost 或 HTTPS）。
3. 到「設備設定」把設備類型切換成「ESP32 實機（藍牙）」。
4. 按「連接 ESP32 設備」，在瀏覽器視窗選擇 **BlinkAssist**。
5. 到「馬達設定」從小角度開始設定，儲存並套用後，再到「日間模式」按「執行一次眨眼」。

實機模式與模擬模式的差異：

| 項目           | 模擬設備                   | ESP32 實機                                                    |
| -------------- | -------------------------- | ------------------------------------------------------------- |
| 設定儲存位置   | 瀏覽器 localStorage        | ESP32 的 NVS，斷電保留                                        |
| 網頁關閉後     | 停止                       | 設備依已套用的設定繼續運作                                    |
| 時鐘           | 電腦時間，可用模擬工具調整 | 每次連線時由前端對時；斷電重開後需重新連線，排程才會恢復      |
| 角度上限       | 0–90°（展示用）            | 由韌體 `config.h` 的 `MAX_CLOSE_ANGLE_DEG` 決定，超過會被拒絕 |
| 改名、模擬時鐘 | 有                         | 沒有（介面會自動隱藏）                                        |
| 畫面上的眼睛   | 前端計算                   | 韌體回報的狀態                                                |

「儲存成功」「套用成功」都必須等設備回覆確認才會顯示；設備 5 秒內沒有回應或中途斷線，一律顯示失敗。通訊協議的完整定義在 [`docs/ble-protocol.md`](docs/ble-protocol.md)。

## 尚未完成

- 韌體尚未在實體 ESP32 與 MG90S 上驗證，只確認能以 Arduino-ESP32 3.3.12 編譯。
- 藍牙沒有配對或加密，範圍內任何人都能連線下指令。
- 沒有位置回授，畫面顯示的是韌體送出的角度，不是馬達實際到達的角度。
- 沒有實體緊急停止、故障釋放機制，也沒有機械限位與力量限制。
- 醫療與機械安全驗證。

以上完成之前，本系統只能用在桌面模型上。

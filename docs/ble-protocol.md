# Blink Assist 藍牙通訊協議（版本 2）

這份文件是前端與韌體之間的合約。實作在兩處，修改協議時三者必須一起改：

- 前端：`src/device/ble/protocol.ts`
- 韌體：`firmware/BlinkAssist/protocol.h`、`settings.cpp`、`BlinkAssist.ino`（`buildStatus`）

不相容的修改（欄位位置、長度、意義改變）必須把協議版本加一。前端連線時會檢查版本，不一致就拒絕連線。

版本紀錄：

- **2**：眨眼間隔的意義由「這次開始到下次開始」改為「這次眨完到下次開始」；取消「間隔不可短於完整眨眼時間」的限制（設定錯誤碼 3 停用）。位元組配置不變。
- **1**：初版。

## 設計原則

- **設備自己執行。** 排程、眨眼計時、馬達控制都在韌體內，網頁關閉或斷線後照常運作。前端只送指令、顯示設備回報的狀態。
- **每個指令都有明確的結果。** 前端寫入指令後，必須收到設備的結果通知才算成功。逾時（5 秒）或斷線一律視為失敗。「儲存成功」代表設備已驗證設定、寫入 NVS 並讀回確認。
- **設備是驗證的最後一關。** 前端會先驗證以便提早提示，但韌體會獨立再驗一次，且角度上限由韌體的 `config.h` 決定，前端無法放寬。
- **使用固定長度的二進位格式，不用 JSON。** 整份設定只有 20 bytes。藍牙協定本身會處理超過單一封包的讀寫（長讀取／長寫入，上限 512 bytes），所以不需要自訂分段與重組。通知沒有這個機制，因此狀態封包控制在 16 bytes，低於最小封包容量 20 bytes。

所有多位元組欄位皆為 **little-endian**。

## GATT 服務

服務 UUID：`12345678-1234-1234-1234-123456789000`

| 尾碼   | 名稱         | 屬性         | 內容                     |
| ------ | ------------ | ------------ | ------------------------ |
| `9001` | 已儲存的設定 | READ         | 設定（20 bytes）         |
| `9002` | 狀態         | READ、NOTIFY | 狀態（16 bytes）         |
| `9003` | 指令         | WRITE        | `seq`、`opcode`、payload |
| `9004` | 指令結果     | NOTIFY       | 結果（4 bytes）          |
| `9005` | 執行中的設定 | READ         | 設定（20 bytes）         |

「已儲存」是 NVS 裡的內容；「執行中」是設備目前實際使用的設定。兩者在套用（或重新載入）後才會一致。

## 設定（20 bytes）

| 位移 | 長度 | 欄位              | 說明                                               |
| ---- | ---- | ----------------- | -------------------------------------------------- |
| 0    | 1    | 設定版本          | 目前為 `1`                                         |
| 1    | 1    | 旗標              | bit0 啟用日間眨眼；bit1 啟用夜間排程；其餘必須為 0 |
| 2    | 4    | 眨眼間隔（ms）    | 1,000–10,000；這次眨完到下次開始（睜眼的時間）     |
| 6    | 2    | 閉眼時間（ms）    | 100–10,000                                         |
| 8    | 2    | 閉眼停留（ms）    | 0–10,000                                           |
| 10   | 2    | 睜眼時間（ms）    | 100–10,000                                         |
| 12   | 2    | 排程開始          | 從午夜起算的分鐘數，0–1439                         |
| 14   | 2    | 排程結束          | 同上                                               |
| 16   | 1    | 星期遮罩          | bit n 代表星期 n（0 為週日）；是排程的「開始日」   |
| 17   | 1    | 左側閉眼角度（°） | 0 到韌體上限；`0xFF` 代表未設定，該側不會轉動      |
| 18   | 1    | 右側閉眼角度（°） | 同上                                               |
| 19   | 1    | 保留              | 必須為 0                                           |

其他規則：啟用排程時必須至少選一天，且開始不等於結束。眨眼間隔與眨眼本身的長度之間沒有限制；兩次眨眼開始的時間差是「閉眼＋停留＋睜眼＋間隔」。

對照基準（預設設定），前端測試 `protocol.test.ts` 會檢查這組位元組：

```text
01 01 88 13 00 00 F4 01 2C 01 F4 01 28 05 A4 01 7F FF FF 00
```

即：日間啟用、間隔 5,000 ms、閉眼 500／停留 300／睜眼 500 ms、排程停用（22:00–07:00、每天）、兩側角度未設定。

## 狀態（16 bytes）

| 位移 | 長度 | 欄位              | 說明                                          |
| ---- | ---- | ----------------- | --------------------------------------------- |
| 0    | 1    | 協議版本          | 目前為 `2`                                    |
| 1    | 1    | 韌體主版本        |                                               |
| 2    | 1    | 韌體次版本        |                                               |
| 3    | 1    | 旗標              | 見下表                                        |
| 4    | 1    | 進度              | 0–255；0 為全開，255 為到達閉眼參考角度       |
| 5    | 1    | 左側目前角度（°） | 韌體實際送給伺服的閉眼角度；`0xFF` 代表未設定 |
| 6    | 1    | 右側目前角度（°） | 同上                                          |
| 7    | 1    | 保留              |                                               |
| 8    | 4    | 設備本地時間      | 本地時間秒數（見「時間」）；未對時為 0        |
| 12   | 4    | 距離下次眨眼      | 毫秒；`0xFFFFFFFF` 代表目前沒有排定           |

旗標：

| 位元 | 欄位   | 值                                     |
| ---- | ------ | -------------------------------------- |
| 0–1  | 模式   | 0 待機、1 日間、2 夜間                 |
| 2–3  | 來源   | 0 日間設定、1 自動排程、2 手動夜間     |
| 4–5  | 階段   | 0 睜眼、1 閉眼中、2 閉眼停留、3 睜眼中 |
| 6    | 已對時 | 1 代表設備知道現在時間                 |
| 7    | 保留   |                                        |

通知時機：旗標改變時立即通知；眨眼進行中每 100 ms；其餘每 1 秒。

## 指令與結果

指令寫入 `9003`：`[seq][opcode][payload...]`。`seq` 由前端遞增（0–255 循環），設備在結果中原樣帶回，前端用它把結果對應到指令。前端一次只送一個指令，等到結果或逾時才送下一個。

| opcode | 名稱     | payload              | 說明                                                  |
| ------ | -------- | -------------------- | ----------------------------------------------------- |
| `0x01` | 儲存設定 | 設定（20 bytes）     | 驗證後寫入 NVS。不會改變執行中的設定                  |
| `0x02` | 套用設定 | 無                   | 改用已儲存的設定執行，並重新起算眨眼間隔              |
| `0x03` | 手動夜間 | 1 byte（0 關、1 開） | 即時指令，不儲存。開啟期間優先於自動排程              |
| `0x04` | 立即眨眼 | 無                   | 夜間或眨眼進行中會被拒絕。下次自動眨眼從這次眨完起算  |
| `0x05` | 重新載入 | 無                   | 從 NVS 重新載入並套用，手動夜間回到關閉。連線不會中斷 |
| `0x06` | 對時     | uint32 本地時間秒數  | 前端每次連線後自動送出                                |

結果由 `9004` 通知：`[seq][opcode][結果碼][detail]`。

| 結果碼 | 意義                 | detail     |
| ------ | -------------------- | ---------- |
| 0      | 成功                 | 0          |
| 1      | 指令長度不正確       | 0          |
| 2      | 不認得的 opcode      | 0          |
| 3      | 設定無效             | 設定錯誤碼 |
| 4      | 寫入儲存區失敗       | 0          |
| 5      | 夜間模式中，無法眨眼 | 0          |
| 6      | 眨眼進行中           | 0          |

設定錯誤碼：1 版本不支援、2 日間時間超出範圍、3 已停用（版本 1 為「間隔短於完整眨眼時間」）、4 排程時間或星期格式錯誤、5 排程未選星期或起迄相同、6 角度超過韌體上限、7 格式錯誤（長度或保留位元）。

## 時間

ESP32 沒有電池供電的時鐘，斷電後不知道現在幾點，也沒有時區概念。因此：

- 前端每次連線後送出**本地時間秒數**：把牆上時鐘顯示的時間當成 UTC，換算成 1970 年起算的秒數。也就是 `UTC 秒數 − getTimezoneOffset() × 60`。
- 設備用它直接算出星期（`(秒數 ÷ 86400 + 4) mod 7`，0 為週日）與當天的分鐘數，判斷夜間排程。
- **未對時前，自動夜間排程不會啟動**（狀態旗標 bit6 為 0）。日間眨眼與手動夜間不受影響，因為它們只依賴開機後經過的時間。
- 設備斷電重開後需要重新連線一次才能恢復排程。日光節約時間切換後也需要重新連線對時。

## 連線流程

1. 瀏覽器以服務 UUID 篩選並讓使用者選擇設備，建立 GATT 連線。
2. 訂閱 `9004`（結果）與 `9002`（狀態）的通知。
3. 讀取狀態，確認協議版本一致；不一致則中斷並顯示錯誤。
4. 送出對時指令。
5. 讀取 `9005` 取得執行中的設定，再讀一次狀態。
6. 前端另行讀取 `9001` 載入已儲存的設定到表單。

## 已知限制

- **沒有配對或加密。** 藍牙範圍內的任何人都能連線並下指令。在用於桌面模型以外的場合之前，必須加上配對與加密。
- 同一時間只支援一個連線。
- 設備名稱固定為韌體 `config.h` 的 `DEVICE_NAME`，無法從前端修改。

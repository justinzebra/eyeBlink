# Blink Assist 伺服角度與限速調查報告

更新日期為 2026-11-16（台灣時間）。

## 實機觀察

使用者回報，左右閉眼參考角度設為 90° 後，觀察到馬達只轉到約二十幾度。同期提供的即時模型截圖顯示左右各 **26.0°**，當下階段為「睜眼」。截圖只記錄一個時點，尚無完整循環的角度曲線或實體量測可判斷峰值。

直接查看 Chrome 中的前端時，狀態列顯示「ESP32 已連線」及「已套用」，介面顯示「設備已套用儲存設定」。現場讀到的數值如下。

| 項目             | 已套用值 |
| ---------------- | -------- |
| 左側閉眼參考角度 | 90°      |
| 右側閉眼參考角度 | 90°      |
| 眨眼間隔         | 9 秒     |
| 閉眼時間         | 200 毫秒 |
| 閉眼停留時間     | 150 毫秒 |
| 睜眼時間         | 200 毫秒 |

## 韌體如何產生角度與階段

- 韌體的閉眼角度上限為 90°，速度上限為每秒 300°。依 10 毫秒的標稱主迴圈週期，每圈最多把送出的角度改變 3°。實際迴圈若較長，角度變化會更慢。[韌體參數](../firmware/BlinkAssist/config.h)、[伺服輸出](../firmware/BlinkAssist/servo_driver.cpp)
- 90°／200 毫秒需要每秒 450°。以韌體上限計算，從 0° 到 90° 至少需要 300 毫秒。閉眼階段結束時，輸出角度可能還未到 90°。如果停留結束前沒有追上，睜眼階段的目標會逐漸下降，輸出角度可能在抵達 90° 前就開始返回。[眨眼時間軸](../firmware/BlinkAssist/blink_engine.cpp)
- 階段依眨眼時間軸計算，畫面的角度來自韌體限速後送給伺服馬達的指令。韌體在階段切換時會回報一次，進入睜眼靜止階段後則約每秒回報一次。畫面因此可能在階段已顯示「睜眼」時，仍短暫顯示回程中尚未歸零的角度。伺服馬達沒有位置回授給 ESP32，頁面無法量到實際轉軸位置。[狀態封包與回報](../firmware/BlinkAssist/BlinkAssist.ino)、[藍牙協議](ble-protocol.md)

用上述參數、固定每 10 毫秒更新的簡化推算中，輸出在 200 毫秒約達 60°，在停留階段可追到 90°，到 550 毫秒切成「睜眼」時仍約為 30°。這能解釋截圖中的階段與角度為何不同步。這組推算是理想的韌體輸出範例，本次測試尚未量到馬達是否實際到過 90°，也未確認馬達本身的最高轉速。

## 桌面模型複驗

1. 只在桌面模型上空載測試，角度先使用已確認不會使機構卡住的小角度。可先把閉眼與睜眼時間各設為 500 毫秒，停留設為 300 毫秒，再依序儲存、套用。保留現有韌體的速度與角度限制。
2. 在「日間模式」執行一次眨眼，同時觀察整個週期的回報角度與實體轉軸。可用帶刻度的參考線和錄影比對停留階段的峰值、以及回到起點的時間。變更上述前端參數無須重新燒錄。
3. 若回報角度已達設定值，但轉軸的實際行程仍不足，先查空載時的行程、馬達電源、共地與機構阻力。若回報角度本身仍偏低，先確認整個週期的數字、當時運作模式與已套用設定，再檢查韌體更新週期及 PWM 輸出。[接線與故障排除](../firmware/README.md)

本次僅讀取前端現行設定並核對程式，沒有改動設備設定或觸發動作。整個眨眼週期的實體轉角、PWM 與負載下的電源狀態仍待量測。實機控制只限桌面模型，尚未完成機械限位、力量限制、故障釋放與醫療安全驗證。

# Blink Assist 韌體（ESP32-WROOM-32 + MG90S）

> **僅供桌面模型測試。** 尚未完成機械限位、力量限制、故障釋放與醫療安全驗證，請勿裝在人身上。

這份韌體讓 ESP32 自己執行眨眼與日夜排程，並透過藍牙接受前端的設定與指令。網頁關閉或斷線後，設備仍會依已套用的設定繼續運作。

## 需要的東西

- ESP32-WROOM-32 開發板（Arduino IDE 的開發板選 **ESP32 Dev Module**）
- MG90S 伺服馬達 1–2 顆
- **獨立的 5V 電源，建議 2A 以上**（例如 USB 行動電源模組或 5V 變壓器）
- 建議：一顆 470–1000µF 的電解電容，跨接在伺服電源的 5V 與 GND 之間
- 電腦版 Chrome 或 Edge（支援 Web Bluetooth），電腦需有藍牙

## 接線

MG90S 三條線：**棕色＝GND、紅色＝5V、橘色＝訊號**。

| MG90S           | 接到                   |
| --------------- | ---------------------- |
| 左側 橘（訊號） | ESP32 **GPIO 18**      |
| 右側 橘（訊號） | ESP32 **GPIO 19**      |
| 紅（5V）        | **外接 5V 電源的正極** |
| 棕（GND）       | 外接 5V 電源的負極     |

另外**一定要把外接電源的負極和 ESP32 的 GND 接在一起**（共地），否則訊號沒有參考電位，馬達會亂抖或不動。

```text
外接 5V (+) ────────┬──────── 左伺服 紅
                    └──────── 右伺服 紅
外接 5V (−) ──┬─────┬──────── 左伺服 棕
              │     └──────── 右伺服 棕
              └────────────── ESP32 GND
ESP32 GPIO18 ──────────────── 左伺服 橘
ESP32 GPIO19 ──────────────── 右伺服 橘
ESP32 ─── USB ─── 電腦（供電與燒錄）
```

**不要用 ESP32 的 3.3V 腳位供電給伺服。** 也不建議用開發板的 5V／VIN 腳位：MG90S 啟動或卡住時單顆瞬間電流可達 0.6A 以上，會把 USB 供電拉低，造成 ESP32 重開機或藍牙斷線。只接一顆、不帶負載地試轉時，用 VIN 腳位通常能動，但遇到不明原因的重開機，先懷疑電源。

只有一顆伺服也可以，另一側不接、在前端不要設定該側的角度即可。

要換接腳，改 `BlinkAssist/config.h` 的 `LEFT_SERVO_PIN`、`RIGHT_SERVO_PIN`。

## 燒錄步驟（Arduino IDE 2）

1. **安裝 ESP32 開發板套件**：`工具 → 開發板 → 開發板管理員`，搜尋 `esp32`，安裝 **esp32 by Espressif Systems**（本韌體以 3.3.12 版編譯驗證；程式也保留了 2.x 的寫法，但未實際編譯過）。
   - 若搜尋不到：`檔案 → 偏好設定 → 額外的開發板管理員網址` 填入
     `https://espressif.github.io/arduino-esp32/package_esp32_index.json`
2. **開啟專案**：`檔案 → 開啟`，選 `firmware/BlinkAssist/BlinkAssist.ino`。IDE 會把同資料夾的 `.h`、`.cpp` 一起以分頁開啟，這是正常的。
3. **選擇開發板與連接埠**：`工具 → 開發板 → esp32 → ESP32 Dev Module`；`工具 → 連接埠` 選插上 ESP32 後出現的 COM 埠。其餘選項維持預設。
4. **第一次燒錄前先不要接伺服的機構**，讓馬達空轉即可。
5. 按 **上傳**（→ 圖示）。若卡在 `Connecting......`，按住開發板上的 **BOOT** 鍵直到開始寫入再放開。
6. 上傳完成後設備會自動重啟。兩顆伺服會轉到「睜眼」位置（預設 0°）後靜止。

**上傳前先確認晶振頻率。** 上傳時下方的輸出視窗會印出 `Crystal is 26MHz` 或 `Crystal is 40MHz`。`config.h` 的 `MAIN_XTAL_MHZ` 必須與它相符：40 MHz 的板子填 `0`，26 MHz 的板子填 `26`。目前的值是 `26`（使用者手上的板子是 26 MHz）。填錯時序列埠會變亂碼、藍牙掃不到、伺服脈波走樣，所以確認相符之前不要接馬達。

不需要安裝任何額外函式庫：藍牙、PWM、NVS 都使用 ESP32 套件內建的功能。

## 第一次連線測試

1. 啟動前端（專案根目錄執行 `npm run dev`），用 Chrome 或 Edge 開啟顯示的網址。
2. 到「設備設定」頁，把設備類型切換成 **ESP32 實機（藍牙）**，頁面會重新載入。
3. 按「連接 ESP32 設備」，在瀏覽器跳出的視窗選 **BlinkAssist**，按配對。
4. 連上後狀態列顯示「已套用」，設備資訊顯示韌體版本。此時馬達不會動，因為角度預設為「未設定」。
5. 到「馬達設定」頁，先設一個**小角度（例如 20°）**，按「儲存設定」再按「套用設定」。
6. 到「日間模式」頁按「執行一次眨眼」，伺服應該轉到 20° 再回到 0°，畫面上的眼睛同步開闔。
7. 確認方向與行程正確後，再逐步加大角度。

## 調整安裝方向與行程

都在 `BlinkAssist/config.h`，改完要重新上傳：

- **方向相反**：把該側改成 `OPEN_DEG = 180`、`DIRECTION = -1`。兩顆伺服鏡像安裝時通常其中一顆需要這樣設。
- **睜眼位置不在 0°**：調整 `LEFT_OPEN_DEG`／`RIGHT_OPEN_DEG`。
- **限制最大角度**：把 `MAX_CLOSE_ANGLE_DEG` 調低到機構實測的安全值。前端送來超過這個值的設定會被設備拒絕，前端無法繞過。
- **轉動太快或太慢**：`MAX_SERVO_SPEED_DEG_PER_SECOND`（預設每秒 300°）是轉速上限。進出夜間模式、套用新角度時馬達會以這個速度移動，不會全速甩過去。眨眼的速度由前端的閉眼／睜眼時間決定，超過上限才會被限制。
- **行程不足或頂到底發出嗡嗡聲**：MG90S 個體差異大，微調 `SERVO_MIN_PULSE_US`／`SERVO_MAX_PULSE_US`。

## 行為說明

- **設定存在設備上**（NVS），斷電不會遺失。儲存只是寫入，要「套用」才會改變執行中的行為。
- **角度未設定的那一側不會轉動。** 剛燒錄完的設備兩側都是未設定，所以在你明確設定前馬達不會動。
- **手動夜間是即時指令**，不儲存，設備重啟後一律為關閉。
- **時鐘靠連線對時。** ESP32 沒有電池時鐘，斷電重開後不知道現在幾點，此時**自動夜間排程不會啟動**，直到前端重新連線一次。日間眨眼與手動夜間不受影響。
- **斷線後繼續運作**，並持續廣播，隨時可以重新連線。
- **夜間模式會讓伺服持續出力保持閉眼位置。** MG90S 長時間頂著負載會發熱、耗電，機構設計上應避免讓它長時間對抗阻力。

## 已知限制

- **藍牙沒有配對或加密**，範圍內任何人都能連線並下指令。只適合在桌面測試環境使用。
- 沒有位置回授：畫面上的角度是韌體「送出」的角度，不是馬達實際到達的角度。馬達卡住時設備不會知道。
- 沒有實體的緊急停止或故障釋放機制。
- 韌體只確認能編譯，**尚未在實體 ESP32 與 MG90S 上驗證**。第一次使用請照上面的步驟從空轉、小角度開始。

## 故障排除

| 現象                                               | 可能原因                                                                                       |
| -------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 瀏覽器的選擇視窗找不到 BlinkAssist                 | 電腦藍牙未開啟；設備已被另一個分頁或另一台裝置連線；用的不是 Chrome／Edge                      |
| 找不到 BlinkAssist，且序列埠要設 74880 才讀得懂    | 板子的主晶振是 26 MHz 但 `config.h` 的 `MAIN_XTAL_MHZ` 是 `0`；改成 `26` 重新上傳              |
| 連線後馬上斷線、設備一直重開機                     | 伺服電源不足，改用獨立 5V 電源並加電容                                                         |
| 馬達抖動或不動                                     | 沒有共地；訊號線接錯腳位；電源不足                                                             |
| 按眨眼沒反應                                       | 該側角度仍是「未設定」；設定儲存了但還沒套用；目前在夜間模式                                   |
| 連得上、讀得到設定，但「儲存設定」一直逾時或被拒絕 | 儲存指令長 22 bytes，需要藍牙的長寫入；若只有這個指令失敗，請回報，可能要在韌體調高 MTU        |
| 每個指令都顯示「設備沒有回應」                     | 通知沒有送達；先在 Windows 藍牙設定中移除 BlinkAssist 再重新連線（Windows 會快取舊的服務內容） |
| 顯示協議版本不一致                                 | 前端與韌體版本不同步，重新上傳韌體                                                             |
| 自動夜間排程沒有啟動                               | 設備斷電後尚未重新連線對時                                                                     |

通訊協議的完整定義見 [`docs/ble-protocol.md`](../docs/ble-protocol.md)。
